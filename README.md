# boss姥爷（boss-job-apply）· BOSS 直聘投递助手（多宿主通用技能）

> 显示名：**boss姥爷**；技能标识符（目录名/frontmatter `name`）：`boss-job-apply`。平台要求标识符只能用小写字母、数字和连字符，因此中文名只作为显示名写在 `metadata.display_name` 里，文件夹名保持 `boss-job-apply` 不可改。

一个与宿主 AI 工具解耦的通用技能：在 BOSS 直聘网页端按个人画像检索岗位、逐条进详情页复核，给明确对口的岗位发默认招呼语；拿不准的边缘岗位渐进攒批生成含完整 JD 的拍板表交本人人工标注，标注样本覆盖主要场景后同类已知岗位可按学到的口径自行判定；每日启动先复盘昨日岗位与职责并把结论回写配置；全程台账去重、当日复盘，标注结论回写画像规则，越用越准。

技能本体由一份指令文件（`SKILL.md`）+ 一组 Python CLI 脚本 + 规则参考 + 画像模板 + 版本清单组成；当前在**豆包办公（豆包工作区）**实测可用，流程与脚本与宿主解耦，也可适配其他具备浏览器自动化与终端能力的 AI 工具（见 4.2）。

> 技能本身只包含通用流程与占位模板，**不内置任何人的简历、公司黑名单、联系方式等个人信息**；所有个人配置都在你本地的 `profile.json` 里，不随技能文件提交。

## 一、功能特性

- **关键词轮转 + 全量翻页遍历**：按画像方向顺序逐个搜索，每个关键词滚动到底加载全部卡片、翻遍末页，采完走完复核投递闭环再换下一个；禁止只看第一屏或前几页。
- **当日达标停止**：台账已投累计达到 `daily_goal`（示例 100 份）即停止继续检索；关键词跑完仍未达标才复盘扩方向，不放宽硬排除、不降低薪资与活跃度门槛凑数。
- **拟人化操作**：动作间隔随机、分段滚动、详情页停留读 JD、列表→详情→列表往返轨迹、打招呼前后停顿且两条之间留 2–5 分钟、每小时限速、连续操作后强制休息、只在活跃时段发起——让操作轨迹像真人浏览，而不是脚本批量点击。
- **风控熔断**：一旦出现验证码/滑块/设备验证/「操作过于频繁」/按钮变灰/发送失败等信号，立即停机交本人，冷却后减半放量；触发计数写入台账按日累计，当日熔断达上限即收工、剩余目标顺延次日；绝不过验证、不换 IP/UA、不多账号、不并发。
- **列表层预筛、详情页复核**：列表层先按台账去重、标题/主体排除词、活跃度、薪资交集预筛；真实薪资和完整 JD 一律进详情页读取（列表薪资加密）。
- **三分类决策**：`apply`（可投）→ 打招呼；`exclude`（硬排除）→ 记台账跳过原因；`hold`（拿不准）→ 进拍板表，不自行放行也不自行排除。
- **每日复盘回写配置**：启动先回看昨日已沟通岗位的职责/JD 与回复情况，归纳方向、栈、职责命中结论，回写本地画像词表与规则。
- **渐进式拍板攒批**：投递过程中待定岗位每攒够一批阈值就出一张拍板表，不必等当日全部跑完。
- **学习饱和后自行判定**：标注样本达到数量门槛且主要场景被覆盖后，同类已知岗位可按学到的口径自行判定；新场景仍交人工拍板，硬排除类别永不自动放行。
- **台账去重**：已投、已跳过的岗位自动去重，不重复打招呼；随时查看累计统计。
- **人工拍板闭环**：待定岗位导出 xlsx 拍板表（附完整 JD），标注「可投/不投」后解析分组，按标注执行并沉淀新规则。
- **版本自检**：启动时对比本地与上游版本，有新版本时提示升级并附改动摘要；不自动覆盖本地文件。
- **规则与个人配置分离**：流程写死在技能里，个人方向、薪资带、词表、短板全部读本地 `profile.json`。
- **配置分层（正本 / 历史库 / 工作目录产物）**：精简正本只放现行规则与画像，启动全文必读；历史记录库只存每日流水、复盘轮次与误投留痕，按需检索、不进启动上下文；台账、拍板表、标注结果、复盘小结、风控事件、外包知识库均为工作目录产物，不回写正本、不提交仓库。
- **宿主无关**：浏览器操作、脚本执行、表格标注都走中性约定，不绑定某一款 AI 工具的内部接口。

## 二、仓库结构

```text
boss-job-apply-repo/
├── README.md                        # 本说明文档（仓库根目录，安装时不用复制）
└── boss-job-apply/                  # 技能文件夹，整体复制到宿主工具的指令目录
    ├── VERSION                      # 当前版本号与上游仓库清单（机器可读，供版本自检）
    ├── SKILL.md                     # 主流程、安装说明、工作流（加载后必读）
    ├── assets/
    │   └── profile.example.json    # 画像配置模板，复制为 profile.json 后填写
    ├── references/
    │   ├── filters.md               # 薪资口径、硬排除清单、复核清单、拍板协议、打分启发式、行动边界
    │   ├── pacing.md                # 拟人节奏、会话节律、风控熔断与禁止项
    │   └── changelog.md             # 各版本改动摘要，升级提示时按版本号提取
    └── scripts/
        ├── salary_match.py          # 单条薪资串与目标带是否有交集判定
        ├── rank_candidates.py       # 台账去重、标题/主体/活跃度预筛、打分排序、切批次
        ├── ledger.py                # 台账初始化、已投/已跳过追加、去重、统计
        ├── build_decision_sheet.py  # 待定池 → 含完整 JD 的拍板表 xlsx
        ├── parse_annotation.py      # 解析标注表，拆 apply / exclude / blank
        ├── pacing_plan.py           # 按动作随机生成等待表（限速 + 休息 + 时段顺延）
        └── version_check.py         # 对比本地与上游版本，输出升级提示与改动摘要
```

> 技能文件夹内 `scripts/`、`references/`、`assets/` 的相对引用不能拆散；`README.md` 是给人看的说明，不需要复制进指令目录。

## 三、环境要求

### 4.4 安装依赖（可选但建议）

终端执行：`pip install openpyxl`。只用预筛/台账、不跑拍板表可以先不装。

### 4.5 触发方式

重启或刷新宿主工具后，在对话中描述「BOSS 直聘 / 打招呼 / 投递 / 筛岗」等任务即可加载本指令；也可以直接说「按 boss-job-apply 流程跑今日投递」。

### 4.6 宿主适配约定

技能不绑定宿主内部接口，各宿主按以下约定对接：

- **浏览器**：宿主用自己的浏览器自动化能力打开页面、滚动列表、翻页、读取详情、点击「立即沟通」；验证码、扫码、设备验证一律交本人接管。
- **终端**：脚本通过宿主的终端/命令执行能力运行，命令见第八节；工作目录为本次投递任务的本地文件夹。
- **文件**：`profile.json`、`candidates.json`、`ledger.json`、拍板表等产物都落在工作目录，技能目录本身只读复用。
- **标注渠道**：拍板表 xlsx 可导入任意在线表格或本地 Excel，宿主任选本人常用的协作渠道交付标注。

## 五、第一步：登录 BOSS 直聘

技能通过宿主工具的浏览器能力操作网页端，登录这一步必须由你本人完成，技能不会也不能绕过登录。

### 5.1 打开网页

- 方式一（推荐）：直接对宿主助手说「打开 BOSS 直聘岗位页」，由其浏览器自动化导航到岗位列表页：
  `https://www.zhipin.com/web/geek/jobs?city=<城市码>&query=<关键词>`
- 方式二：自己在宿主浏览器地址栏输入 `https://www.zhipin.com` 回车。

### 5.2 完成登录

1. 若页面跳到登录页，选择登录方式：
   - **手机号 + 短信验证码**：输入本人手机号，填写收到的 6 位验证码；
   - **App 扫码**：打开手机 BOSS 直聘 App，用扫码功能扫页面二维码。
2. 中途如果出现**滑块验证、短信二次校验、设备验证、人脸验证**，由你本人手动完成；技能会停在该页面等你接管，不会尝试自动破解。
3. 登录成功后页面会回到岗位列表/首页。

### 5.3 怎么确认登录态有效

- 页面**右上角显示你本人的头像和昵称** = 已登录，可以继续流程；
- 如果右上角是「登录/注册」按钮，或页面反复跳回登录页 = 未登录/登录态失效，重新走 5.2。

### 5.4 登录后的注意事项

- 全程保持这个浏览器标签页的会话，不要清理浏览器 Cookie；
- 岗位检索、详情页、打招呼都在这个已登录会话里完成；
- 离开很久后回来发现掉线，重新扫码/验证码登录即可；
- 技能不保存你的密码、验证码、Cookie；这些只存在于当前浏览器会话中。

## 六、第二步：配置求职意向 profile.json

`profile.json` 是你和技能之间唯一的个人配置入口。**首次使用必须先配置，否则脚本会用通用默认值，方向和薪资都不对口。**

### 6.1 创建配置文件

1. 在本次工作目录（你跑投递任务的本地文件夹）中，复制一份模板：

   - 源文件：技能目录 `boss-job-apply/assets/profile.example.json`（技能目录在本机的位置以已安装技能所在文件夹为准，常见路径为 `.user_skills/boss-job-apply/`、`~/.claude/skills/boss-job-apply/` 或 `~/.dsh/skills/boss-job-apply/`）
   - 目标文件：工作目录下的 `profile.json`

2. **必填字段**：城市与城市码、薪资带、方向关键词、主/副栈、弱点、排除词表、活跃度标签、拍板与学习饱和配置。模板里的 `<...>` 都是占位符，必须替换；带示例数值的字段（如薪资带）也要换成你自己的。

3. **信息采集与录入顺序**：
   - 先在已登录的本人 BOSS 会话里，直接打开你的主页/在线简历，采集页面可见的城市、工作年限、学历、技术栈、期望薪资、求职状态等信息回填 `profile.json`；只读取你本人账号可见的内容，不改写 BOSS 简历，不采集未公开信息；
   - 登录成功后同步读取**在线简历与附件简历**中的「个人优势」「项目经历」（角色、职责、所用技术栈、可量化成果），提炼成画像条目写入 `profile.json`；附件简历需你同意打开后再读，不绕过简历查看限制；
   - 简历表述模糊、读不懂、或与你当前情况存疑的字段，**不会不懂装懂、不按常识推测**，会及时向你澄清反问，逐项确认后再录入；你当场补充的信息直接采用；
   - 不会替你臆造年限、学历、技术栈、薪资、优势、项目经历、弱点等事实。

4. **你明确拒绝填写的字段**：保留模板占位符，相关岗位在详情复核时降级为人工判断，不会按默认值擅自放行。
5. **画像确认闸门（首次使用）**：登录完成后，技能先从你的在线/附件简历提取方向、薪资、城市、技术栈、短板等字段；简历写不清的会逐项反问你——目标方向与目标岗位名、薪资区间、目标城市、可投/不投的栈、是否接受外包驻场/单休/特定行业、作息安排。提取结果列成条目回显给你核对，**你确认通过后才开始检索和打招呼**；未确认前不建台账、不投递；你拒绝提供的字段留占位符，相关岗位转人工复核。

### 6.2 字段逐项说明

#### `meta` —— 任务元信息

| 字段 | 含义 | 填写说明 |
| --- | --- | --- |
| `owner` | 你的称呼 | 仅用于本地台账记录，可写昵称；不提交仓库 |
| `city` | 目标工作城市 | 如「上海」；外地 base 的岗位不采集 |
| `city_code` | 城市码 | BOSS 岗位页 URL 里 `city=` 后面的数字。不知道时：先在页面城市选择器里选好目标城市，再看地址栏 URL 中的 `city=` 参数抄下来 |
| `daily_goal` | 每日目标投递份数 | 当天计划打招呼的岗位数量，示例 100；台账 `applied` 累计达到该份数即停止继续检索；未达标且关键词全部跑完才复盘扩方向 |
| `greeting_policy` | 招呼语策略 | 默认只发 BOSS 当前招呼语；未获本人授权不发附件/在线简历、不主动回复招聘方 |

#### `config_sources` —— 配置文档分层

| 字段 | 含义 | 填写说明 |
| --- | --- | --- |
| `primary_doc` | 精简配置正本 | 在线文档链接或本地规则文件路径，只放现行画像与规则，启动时全文必读 |
| `history_doc` | 历史记录库 | 在线文档链接或本地流水文件路径，只存每日投递流水、复盘轮次、误投留痕，按日期检索 |
| `split_rule` | 分层规则 | 新口径当天写正本；每日结果只写历史库；工作目录产物不进启动上下文、不回写正本 |

**三类材料对照**

| 材料 | 放什么 | 不放什么 | 何时读/写 |
| --- | --- | --- | --- |
| 精简正本 | 现行画像、方向词清单、薪资口径、硬排除清单、活跃度门槛、栈匹配口径、动作边界与风控规则 | 每日流水、逐条岗位留痕、多轮复盘记录 | 每次开工第一步全文必读；沉淀后的口径变更才回写 |
| 历史记录库 | 当日已投/跳过/hold 流水、复盘轮次、被拒与误投留痕 | 现行规则、画像口径（规则变更回正本） | 需要按日期检索复盘时读；每日结果只写这里 |
| 工作目录产物 | `ledger.json`、`details.jsonl`、`hold.json`、拍板表、标注结果、`review_yesterday.json`、`risk_events.jsonl`、`outsource_kb.json` | 不复制进正本/历史库、不提交仓库 | 服务当日运行与断点续跑，不进启动上下文 |

> 未配置在线文档时，正本由本地 `profile.json` 与规则文件充当，历史库对应本地台账与复盘小结文件；分层原则不变。

#### `expectation` —— 求职意向与筛选口径

| 字段 | 含义 | 填写说明 |
| --- | --- | --- |
| `positions` | 目标方向/关键词列表 | 检索选词与轮转顺序，只列简历技术栈可覆盖的方向；如「AI 应用开发」「全栈开发」「Java」「后端开发」「Python」「RAG」等，按本人意向列 |
| `salary_band.lo` / `hi` | 目标薪资带下/上限（K） | 如 `18` / `25`。判定口径：岗位区间与 `[lo, hi]` **有交集即投**——岗位下限 ≤ `hi` 且岗位上限 ≥ `lo`，边界值包含 |
| `salary_band.rule` | 薪资规则说明 | 保留模板原文即可，无需改 |
| `keywords_hit` | 命中关键词 | JD/标题里出现即认为方向对口的词 |
| `keywords_bonus` | 加分关键词 | 出现时排序靠前的词（你的主栈、常用框架等） |
| `excluded_companies` | 不想投的公司全称 | 列表层命中即排除；没有就留空数组 `[]` |

| `activity.allowed_labels` | 可接受的活跃标签 | 刚刚活跃/今日活跃/3日内活跃 |
| `activity.zombie_labels` | 僵尸岗标签 | 本周活跃/本月活跃等，命中即不投 |

**薪资交集判定示例**（目标带 18–25K）：

| 岗位薪资 | 判定 | 原因 |
| --- | --- | --- |
| 12~18K | ✅ 有交集 | 上限 18 ≥ 18，边界包含 |
| 15~25K | ✅ 有交集 | 15 ≤ 25 且 25 ≥ 18 |
| 25~35K | ✅ 有交集 | 下限 25 ≤ 25，边界包含 |
| 8~14K | ❌ 无交集 | 上限 14 < 18 |
| 28~40K | ❌ 无交集 | 下限 28 > 25 |

> `·13薪/·14薪/年终奖` 不影响区间判定，只取 K 数；`N·薪` 不是工作年限。

#### `decision` —— 拍板与学习饱和配置

| 字段 | 含义 | 填写说明 |
| --- | --- | --- |
| `hold_batch_size` | 渐进攒批阈值 | hold 池每达到该数量就生成一批拍板表交你标注，默认 6；不足一批的剩余并入下一批 |
| `sheet_channel` | 拍板表交付渠道 | 你常用的在线表格 / 本地 Excel / CSV，与标注习惯一致即可 |
| `saturation.min_annotated_samples` | 饱和样本门槛 | 已标注样本达到该数量才进入饱和判定，默认 30 |
| `saturation.auto_decide_when_covered` | 饱和后是否允许自行判定 | `true`：主要场景覆盖后同类已知岗位可自行 apply/exclude；`false`：所有 hold 一律人工拍板 |
| `saturation.coverage_note` | 场景覆盖口径 | 哪些方向/栈/主体性质/排除类别已有样本覆盖；未出现过的新模式不算已覆盖 |

#### `search_loop` —— 检索轮转与当日目标控制

| 字段 | 含义 | 填写说明 |
| --- | --- | --- |
| `rotate_positions_in_order` | 按 `positions` 顺序轮转 | `true`：按方向列表顺序逐个关键词处理，不按热度随意调换 |
| `collect_all_before_next` | 采完再换词 | `true`：当前关键词全部采集并走完预筛/复核/投递闭环后，再换下一个关键词 |
| `scroll_until_no_new_cards` | 滚动到底 | `true`：单页反复滚动，直到卡片数量不再增长（懒加载全部露出） |
| `traverse_all_pages` | 翻遍全部页 | `true`：逐页翻到末页，禁止只采首屏或前几页 |
| `per_candidate_full_review` | 逐候选复核 | `true`：每个候选岗位都进详情页走复核清单，不按列表标签直接判定 |
| `stop_when_goal_reached` | 达标停止 | `true`：台账 `applied` 达到 `daily_goal` 即停止继续检索 |
| `example_positions` | 示例方向 | 仅作格式参考（AI 应用开发/全栈/Java/后端/Python/RAG 等），按本人简历可覆盖范围替换 |

> 当日各方向沟通份数的分布属于本人实战统计，只写进本地 `profile.json` 或复盘小结，不固化到技能模板。

#### `pacing` —— 拟人操作节奏（重要）

| 字段 | 含义 | 默认/填写说明 |
| --- | --- | --- |
| `enabled` | 是否启用拟人节奏 | `true`；关掉等于机械点击，不建议 |
| `mode` | 速度档位 | `standard`（默认，约 20 条/时）；`conservative` 约 12 条/时（新号/被验证过）；`active` 约 30 条/时（仅长期无验证） |
| `action_ranges` | 各动作等待区间（秒） | 按动作给 `[最小, 最大]`，每次从这里随机取；禁止写死常量 |
| `session_minutes` | 单次连续操作时长 | 由档位给定（conservative 20–30 / standard 25–35 / active 35–45 分钟）；显式填写可覆盖 |
| `rest_minutes` | 休息时长 | 由档位给定（8–15 / 6–12 / 5–10 分钟），休息期间不做任何页面操作 |
| `hourly_greet_cap` | 每小时打招呼上限 | 由档位给定（12 / 20 / 30 条），显式填写可覆盖 |
| `active_hours` | 活跃时段 | 默认 `09:00-21:30`，窗口外不发打招呼 |
| `cards_review_per_greet` | 每投一条前浏览几张卡片 | 默认 3，用于形成自然的浏览轨迹 |
| `daily_hard_cap` | 当日硬上限 | 默认 100，作为 `daily_goal` 的兜底 |
| `ramp_up_note` | 梯度放量提醒 | 新账号先 conservative 跑 3 天（15 → 25 → 40 条/日），无验证再切 standard |

> 预估耗时：`standard` 下 30 条约 1.5 小时、100 条约 5–6 小时；`conservative` 100 条约 8 小时以上；`active` 30 条约 1 小时。用 `python scripts/pacing_plan.py --greets 30 --mode standard` 可以按你的档位精确算出时间表。

| 字段 | 含义 | 默认/填写说明 |
| --- | --- | --- |
| `stop_on` | 停机信号清单 | 验证码、滑块、设备/人脸验证、操作过于频繁、访问异常、账号风险、沟通受限、发送失败 |
| `cooldown_minutes` | 冷却时长 | 默认 120 分钟；冷却后当日剩余份额减半 |
| `max_triggers_per_day` | 当日熔断上限 | 默认 2 次，达到即当日终止自动投递 |
| `stop_day_on_second_trigger` | 二次熔断是否收工 | `true` |
| `never_bypass_verification` | 是否允许过验证 | 必须 `true`（不允许） |
| `no_parallel_tabs` / `no_unsupported_api` | 禁止并发与私有接口 | 保持 `true` |
| `log_file` | 熔断事件日志 | 工作目录下 `risk_events.jsonl` |

| --- | --- |
| `work_years` | 工作年限 |
| `education` | 学历情况 |
| `english` | 英语水平 |

| `secondary_stack` | 副栈/了解的技术 |
| `personal_advantages` | 个人优势摘要，从在线简历/附件简历的个人优势栏提炼 |

### 7.1 拟人节奏与风控熔断（务必按此跑）

投递流水线在网页端必须像真人在浏览、阅读、决策。完整规范见技能内 `references/pacing.md`，参数在 `profile.json` 的 `pacing` / `risk_guard`。

**节奏怎么做**

| 动作 | 停留/间隔 | 要点 |
| --- | --- | --- |
| 输入搜索词后 | 1.5–4 秒 | 等结果渲染，别刚出列表就滚 |
| 单次滚动 | 0.8–2.5 秒 | 每次 300–600px，停住看卡片；禁止一步到底 |
| 读一张卡片 | 1.5–4 秒 | 看标题、公司、活跃标签 |
| 翻页 | 3–8 秒 | 点前回看页尾，翻完停住 |
| 打开详情 | 2–5 秒 | 等 JD 渲染 |
| 读 JD | 8–20 秒 | 越长越久；不读完不打招呼 |
| 打招呼前 / 后 | 3–7 秒 / 4–10 秒 | 点前确认，点后看结果，不立刻跳走 |
| 两条打招呼之间 | 档位决定：conservative 2–5 分钟 / standard 1–2.5 分钟 / active 40–90 秒 | 思考/浏览间隙，别一分钟连投三条 |
| 会话 | 到档位时长即休息（约 20–45 分钟操作 / 5–15 分钟休息） | 休息期间不做任何页面操作 |
| 每小时上限 | conservative 12 / standard 20 / active 30 条 | 账号敏感往下降一档 |
| 活跃时段 | 默认 09:00–21:30 | 窗口外不发打招呼 |

需要一份确定的节奏表时，跑：

```bash
python scripts/pacing_plan.py --greets 12 --profile profile.json --seed 42
python scripts/pacing_plan.py --greets 30 --mode standard --seed 42   # 临时切档看耗时
```

输出里给了每条打招呼的时刻、每步该等多少秒、限速等待与会话休息；脚本只算等待值，不操作页面。

**熔断怎么做（最高优先级）**

出现任一信号：验证码、滑块、点选/设备/人脸验证、安全验证页；「操作过于频繁」「请稍后再试」「访问异常」「账号存在风险」；「立即沟通」变灰、打招呼被吞、消息发送失败；被强制跳回登录页——**立即停机**：

1. 保留页面原状，不刷新、不试探、不重试；
2. 把信号原文与当时动作如实报给你，由你决定人工验证后继续还是当日收工；
3. 可继续时冷却 120 分钟，当日剩余份额减半；
4. 当日熔断满 2 次即当日终止；
5. 事件写入 `risk_events.jsonl` 供复盘。

**绝不做**：过验证码/破滑块、伪造设备或 UA、换 IP/代理池、多账号轮投、调未公开接口、并发多标签批量点、被拦后加速冲量、降门槛凑份数。

> 如实说明：以上措施只能**降低**被风控的概率，不能保证账号不被限制。平台规则、账号历史、同网络环境行为都会影响判定，风险由使用者承担。首次使用请按 `pacing.ramp_up_note` 梯度放量（约 15 → 25 → 40 条/日），账号一旦受限立即停用本技能并按平台申诉流程处理。

```bash
# 已投
python scripts/ledger.py applied-append --eid EID --company 公司名 --title 岗位名 --salary "15-25K" --match "命中方向"

# 跳过（排除）
python scripts/ledger.py skip-append --eid EID --reason "排除原因" --company 公司名 --title 岗位名 --salary "薪资"
```

## 九、筛选规则速览

完整判定依据见 `boss-job-apply/references/filters.md`，核心口径：

1. **薪资**：与目标带区间有交集才进下一轮；列表卡片薪资加密，必须进详情页读真实薪资。
2. **方向**：命中画像 `positions` / 关键词；主栈能对上 JD 必需项，可选加分栈不要求全会。
3. **硬排除**（命中任一即不投）：
   - 用工性质：外包、猎头代招、劳务派遣、驻场、客户现场交付、售前/解决方案；卡片左上角带「猎头」标签或职位/招聘者/公司名含猎头含义的，列表层直接跳过；
   - 角色方向：算法研究/训练微调、产品运营销售、AI Infra/推理部署、数据平台/工具链、与目标方向不符的平台/客户端/数据处理等（以 `filters.md` 清单为准）；
   - 岗位状态：僵尸岗（本周活跃及更久）、过期帖、文化信号负面；
   - 资质栈：全日制/统招/院校硬门槛、画像无法覆盖的唯一硬需技术、短板中的多年硬经验、应届/实习/日薪；
   - 标题管理：架构师/architect 一律排除；纯带团队/梯队培养/非研发负责人岗；
   - 其他：外地 base、明确单休、英语工作语言硬门槛、硬需缺失的特定行业履历。
4. **打招呼前复核清单**：方向命中、薪资有交集、学历可过、甲方自研、无缺失硬技能、不在排除清单、招聘者 ≤3 天活跃、岗位未过期、无待核疑点——全部满足才打招呼。
5. **活跃度门槛**：只投「刚刚活跃 / 今日活跃 / 3日内活跃」；本周活跃及更久视为僵尸岗。

## 十、拍板表（人工标注）闭环

拿不准的岗位（经验深度待核、外包嫌疑、方向边缘、硬门槛模糊等）**不自行放行也不自行排除**，走下面的闭环：

1. **渐进攒批**：投递过程中持续收集待定岗位；每攒够 `profile.json` 的 `decision.hold_batch_size`（默认 6 条），就用 `build_decision_sheet.py` 生成一批拍板表 `decision_sheet_<日期>_batch<N>.xlsx`，列：序号/公司/岗位/薪资/经验/学历/地点/待定原因/岗位链接/完整 JD/你的决定；不足一批的剩余挂起并入下一批。宿主支持飞书文档时（如豆包办公），每批同时生成一份飞书拍板文档，链接放在当天汇报开头并写明「待拍板 N 条」，提醒你拍板。
2. 把 xlsx 导入任意在线表格（飞书表格、Google Sheets、企业微信表格等）或本地 Excel，逐条在「你的决定」列标注 **可投** 或 **不投**；完整 JD 已附在表里，方便核实。
3. 标注回表后用 `parse_annotation.py` 解析：
   - `apply`：补打招呼并记台账；
   - `exclude`：记台账 skipped 并写原因；
   - `blank`：继续挂起，下次再议。
4. 把本次标注得出的新排除类别、放行口径，回写到本地 `profile.json` 词表和 `filters.md` 对应小节，形成学习闭环。
5. **学习饱和后自行判定**：已标注样本达到 `saturation.min_annotated_samples` 且主要场景（方向、栈、主体性质、排除类别）被覆盖时，同类已知场景的 hold 岗位可按学到的口径自行 apply/exclude，判定理由记入台账；未覆盖的新方向/新栈/新主体类型仍进拍板表；**硬排除清单类别任何时候都不自动放行**；饱和开关关闭时所有 hold 一律人工拍板。

## 十一、版本与升级

### 11.1 版本机制

- 技能根目录 `VERSION` 记录当前版本号（语义化 `major.minor.patch`）、上游仓库与分支；`references/changelog.md` 记录每个版本相对上一版的改动摘要。
- 每次启动投递任务前，`version_check.py` 读取本地 `VERSION`，拉取上游仓库同路径的 `VERSION` 与 `changelog.md` 做对比：
  - 上游更新：输出新版本号、本地版本号、区间内各版本的改动条目，并提示你确认后升级；
  - 已是最新：给出确认提示；
  - 网络不可达或仓库不可访问：跳过自检，不阻断当日投递。
- 自检脚本**不会自动覆盖本地技能文件**；升级动作需你本人确认后执行。
- **更新通知**：每次启动投递任务都会跑自检；发现上游有新版本时，版本号、改动摘要和升级步骤会放在当天汇报的开头提示你。技能连续多日没有运行时自检不会触发，建议在 GitHub 仓库页点 Watch → Custom → Releases 勾选 Releases，直接接收发布通知。

### 11.2 怎么升级到新版本

1. 查看自检输出的改动摘要，确认是否升级；
2. 重新克隆或拉取本仓库最新代码（`git pull`），或重新下载压缩包；
3. 用仓库里的 `boss-job-apply/` 整目录覆盖宿主指令目录下的同名文件夹（目录见 4.3）；`scripts/`、`references/`、`assets/`、`VERSION` 一并保持原样；
4. **不要覆盖你的工作目录**：`profile.json`、`ledger.json`、拍板表等本地产物都在工作目录，升级技能目录不影响这些文件；
5. 覆盖后重跑一次 `version_check.py`，确认本地版本号已与上游一致。

### 11.3 版本号约定

- 新增流程、配置块、脚本或判定口径变更 → 次版本号 +1（如 1.1.0 → 1.2.0）；
- 文案、修复、脚本兼容性微调 → 修订号 +1；
- 不兼容的目录结构/协议变更 → 主版本号 +1。

## 十三、边界与安全红线

- 只发 BOSS 当前默认招呼语；**不附附件简历、不主动发在线简历**，未获本人另行授权前一律不发；
- 已显示「继续沟通」的职位不重复点击；不主动回复招聘方聊天，除非本人另行要求；
- 猎头弹层提示「主动联系后简历可见」时取消，不计入新增；
- 同公司同职责不同链接按重复职位审慎处理；不同招聘者或不同职位链接才计新增；
- 采集走浏览器自动化，Python 脚本只做本地去重、排序、台账、制表等后处理；不写爬虫、不调用未公开接口；
- 遇到验证码、扫码、设备验证、登录态失效：停下手头操作交本人接管，不绕过；
- 个人信息（姓名、联系方式、简历项目、公司黑名单）只进本地 `profile.json` 工作目录，不写入技能文件、不提交仓库；
- 控制操作频率，遵守 BOSS 平台规则与用户协议；不批量骚扰招聘方；
- 全程按 `references/pacing.md` 拟人节奏执行（随机间隔、分段滚动、阅读停留、档位限速、强制休息）；命中风控信号立即停机交本人，冷却后减半，当日熔断达上限收工；
- 绝不自动过验证码/滑块、不伪造设备或 UA、不换 IP/代理池、不多账号轮投、不调未公开接口、不并发批量打招呼；
- 节奏与熔断只能降低风控概率，**不能保证账号不被限制**；账号一旦受限立即停用本技能并按平台流程申诉。

## 十四、常见问题 FAQ

**Q：打开页面跳到登录页/一直掉线？**
A：登录态失效，按第五节重新扫码或验证码登录；完成后回到岗位列表页继续。

**Q：岗位卡片显示不全、翻不到后面的职位？**
A：列表是懒加载，先把页面反复滚动到底，等卡片数量不再增长，再点「下一页」；每个关键词都要翻到末页，采完一个关键词的全部结果再换下一个。

**Q：一天要投多少个？什么时候停止？**
A：目标份数在 `profile.json` 的 `meta.daily_goal`（示例 100）；台账 `applied` 累计达到该份数即停止继续检索。所有关键词跑完仍未达标时，技能会复盘缺口再按口径扩方向，但不会放行硬排除类别，也不会降低薪资/活跃度门槛凑数。

**Q：列表上薪资看不清楚/是加密的？**
A：正常现象，列表薪资加密；真实薪资必须进详情页读取，不要凭卡片标签判断薪资是否达标。

**Q：运行拍板表脚本报 `ModuleNotFoundError: openpyxl`？**
A：执行 `pip install openpyxl` 安装；只用预筛/台账不跑拍板表可以先不装。

**Q：之前打过招呼的岗位又出现了？**
A：台账 `ledger.json` 会按 eid 去重；确认台账文件在工作目录且未被删除，已投/已跳过的不会再进候选。

**Q：城市码 `city_code` 怎么填？**
A：在页面城市选择器选好目标城市后，看地址栏 URL 里 `city=` 后面的数字抄进 `profile.json`；列表采集前再在页面城市选择器上双重确认。

**Q：怎么判断一个岗位该不该进拍板表？**
A：只要存在待核疑点（主体性质、驻场痕迹、方向边界、经验深度、硬门槛模糊），就进 hold 池，不要替本人拍板。

**Q：可以把填好的 profile.json 一起提交到仓库吗？**
A：不建议。`profile.json` 含个人意向、栈和短板，只保留在本地工作目录；仓库里只提交占位模板 `profile.example.json`。

**Q：我的宿主工具不在第四节的映射表里，能装吗？**
A：可以。只要宿主能加载外部指令文件（系统提示/项目规则/技能目录）、能执行终端命令、能控制浏览器，把 `SKILL.md` 作为指令加载、整目录保留 `scripts/`、`references/`、`assets/` 即可；脚本命令与浏览器操作约定见第四、八节。

**Q：启动时提示有新版本是怎么回事？会自动覆盖我的技能吗？**
A：`version_check.py` 对比本地 `VERSION` 与上游版本后给出的提示，附改动摘要；不会自动覆盖本地技能目录，需你确认后按第十一节的步骤升级。本地 `profile.json`、台账等工作目录产物不受升级影响。

**Q：一天投多少比较安全？**
A：没有绝对安全的数字。默认 `standard` 档约 20 条/小时（30 条约 1.5 小时、100 条约 5–6 小时）；新号或近期被验证过的先用 `conservative`（约 12 条/时）跑 3 天梯度放量（15 → 25 → 40 条/日），无验证再切档。把 `daily_goal` 直接设成 100 属高强度，务必随时按熔断规则停手，别为了凑数硬跑。

**Q：12 条/小时是不是太慢了？**
A：那是 `conservative` 档，专门留给新号或被验证过的账号。稳定账号在 `profile.json` 把 `pacing.mode` 改成 `standard`（约 20–23 条/时）即可，30 条约 1.5 小时；确认长期没验证过再用 `active`（约 30 条/时）。改完先跑前 20 条观察有没有弹验证，有就立刻回退。

**Q：被弹验证码 / 提示「操作过于频繁」怎么办？**
A：立即停手，把当前页面原样留着，不刷新、不重点、不反复试；技能会把信号写进 `risk_events.jsonl` 并提示冷却 120 分钟，当日第二次熔断就收工。你人工完成验证后可以继续，但当日剩余份额减半；如果反复出现，说明这个量级不适合当前账号。

**Q：能不能帮我过验证码 / 换个 IP 继续？**
A：不能。过验证码、破滑块、伪造设备或 UA、换 IP/代理池、多账号轮投、调未公开接口都在本技能的禁止项里，这类操作等于拿账号冒险，不做。

**Q：什么时候可以不用再给我发拍板样本？**
A：当已标注样本达到 `saturation.min_annotated_samples` 且主要方向/栈/主体类型都有样本覆盖后，同类已知岗位可由技能按学到的口径自行判定；遇到没覆盖过的新场景，仍会生成拍板表交你标注。硬排除类别任何时候都不会自动放行。
